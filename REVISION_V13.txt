LINE SCANNER PRO V13 · REVISION MINUCIOSA
Fecha: 2026-09-22

CORRECCIONES DE ESTA REVISIÓN
1. Corregido un fallo crítico del parser: la letra "v" de palabras como "Liverpool" podía confundirse con el separador "v".
2. Ahora el separador corto requiere "v" como palabra independiente; también se mantienen 🆚 y vs.
3. Corregido el formato con paréntesis vacíos: "Almería vs Celta Fortuna ()" ya no deja "()" pegado al visitante.
4. Se conserva el formato del usuario: "Liverpool vs 0.5 Bournemouth (3)" se interpreta como Bournemouth +0.5 y total 3.
5. Scanner 01 deja de repetir las mismas consultas de eventos para cada partido pegado: usa caché por competición.
6. Los resultados se cachean temporalmente y el monitor agrupa las consultas por competición.
7. Se mantiene búsqueda automática de ligas/eventos y fallback a resultados recientes.
8. La clave es una sola entrada tipo contraseña en la interfaz; no se guarda en localStorage.
9. El service worker V13 sólo cachea recursos de la propia aplicación; no cachea respuestas de APIs externas.
10. Se conserva la línea exacta introducida por el usuario después de enriquecer el partido con datos web.

FUENTE WEB PRINCIPAL
The Odds API v4:
- /sports para descubrir deportes/competiciones.
- /events para eventos in-play y prepartido; no consume cuota según la documentación.
- /odds para cuotas.
- /events/{eventId}/odds para mercados del evento.
- /scores para resultados live/recientes; daysFrom admite 1–3 y live se actualiza aproximadamente cada 30 segundos.
- The Odds API soporta CORS desde cualquier origen HTTP/HTTPS.

LÍMITES QUE NO SE PUEDEN ELIMINAR DESDE EL HTML
- La aplicación no puede fabricar una API key válida ni activar una suscripción.
- La cobertura de resultados depende de las competiciones que The Odds API tenga disponibles para /scores.
- Las cuotas dependen de región, mercado y casas disponibles.
- Una API key escrita en un frontend es visible para ese navegador; por eso no se incluye en GitHub.
- RapidAPI no se fuerza como segunda fuente en V13 porque cada API de RapidAPI requiere su propio host y autenticación X-RapidAPI-Key; agregarlo sin el proveedor/endpoint exacto introduciría otra fuente de fallos. La V13 prioriza una sola fuente coherente.

NO SE DECLARA "100%" HASTA LA PRUEBA CON LA CLAVE REAL DEL USUARIO.
La clave nunca debe enviarse por chat.
